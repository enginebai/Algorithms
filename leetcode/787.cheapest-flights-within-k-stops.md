# [787. Cheapest Flights Within K Stops](https://leetcode.com/problems/cheapest-flights-within-k-stops/)

## Dijkstra
### 標準 Dijkstra 的問題
這題要求從 `src` 到 `dst` 最便宜的航班，但是允許最多轉機 `k` 次。標準的 Dijkstra 是找「只要路徑的價格越便宜，我就更新覆蓋、並且嘗試該路徑」，它只看單一條件，完全不考慮 `k` 次轉機。

以下列例子來看標準 Dijkstra 會發生什麼問題，A 起點、C 終點：
- 航線 1: `A -> B -> C` (A 飛 B 只要 10 元，B 飛 C 只要 10 元，總價 20 元)
- 航線 2: `A -> C` (直飛，總價 50 元)

Dijkstra 過程:
1. 加入 `A(0)`, 彈出 `A` 然後加入 `[B(10), C(50)]`，`prices = [0, oo, oo]`
2. 然後彈出 `B(10)`，加入 `[C(50), C(20)]`，`prices = [0, 10, 20]`
3. 彈出 `C(20)`，到達終點回傳 20。

假設 `k = 0` 不允許轉機，從剛剛過程發現 `C(20)` 我們實際上不知道有沒有轉機，因為 `prices` 表格只有紀錄單一欄位：「價格」，越便宜的路線留下，其他都被淘汰。

> 標準 Dijkstra 的死穴：純粹的唯價格論。它會記錄並覆蓋單一節點的最低價格，導致「雖然較貴，但轉機次數極少」的中庸/救世主路線被提早抹殺。

### 多狀態 Statful Dijkstra 
現在這題，一條路徑不在只有考慮「價格」而已，還有「轉機次數」。一條路徑 50 元雖然較貴，但是他轉機次數為 0，在我們這題來說，是一條有潛力的路徑，不該被較便宜、但轉機次數多的路徑淘汰。意思是，我們 Dijkstra 也需要考慮這兩個狀態，我們 Heap 和路徑狀態表格都需要一起紀錄 `(price, stops)`，然後用這兩個條件去比較和選擇，這就是「多目標最佳化」。

總結，問題的本質是在圖論中尋找最便宜航班，但受到「最多中轉 K 次」的嚴格限制。這是一個典型的「雙維度競爭」問題：路線的優劣由「價格」與「次數」共同決定。

> Q: 這樣我們 Heap 該存什麼？用什麼排序？
先對焦我們「最終目標」：我們要的是「最便宜」而不是「最少站」，轉機次數在這題只是一個「條件限制」，而「價格」才是我們要最佳化的目標，而 Heap 是幫我們決定「探索世界的優先順序」，它必須要為最佳化目標去決定順序，也就是「價格」。(當然我們可以在價格相同時去用「轉機次數」比較)

> Q: 什麼樣的路徑狀態，我們可以納入考慮？ (Relax)
要寫對 Stateful Dijkstra 的條件判斷，請記住一個核心原則：**「只要在任一維度上創下新低，它就有資格活下去。」**
1. 花費較少 (第一優先考量)
2. 轉機次數較少 (次要考量，就算花費較多，但是轉機次數少也可以當作有潛力的路徑。)因為當便宜路徑可能因為總總因素 (到不了終點、轉機次數過多) 而不被考慮時，這條貴一點但是轉機次數少的路徑就可能成為救命稻草。

> Q: 那麼什麼樣的路徑狀態，我們就一概不考慮了？ (Stale)
就是既花費多、而且轉機次數也多的路徑。當然還有轉機次數超過 `k` 的路徑。這就是我們在 Dijkstra 排除 stale 狀態的根據。

> Q: 轉機次數 `k`，那麼總共我們可以走幾步？
我們來看個例子：
- 0 次中轉 (k = 0)：`A -> B`，包含終點，共搭了 1 次飛機 (`k + 1`)。
- 1 次中轉 (k = 1)：`A -> C -> B`，包含終點，共搭了 2 次飛機 (`k + 1`)。
所以你用「包含終點、不含起點，總共可以走 `k + 1` 個 stops（也就是搭 `k + 1` 趟航班）」來思考是絕對正確且最不會搞混的定義方式。

> Q: 路徑狀態表格該怎麼紀錄？
- 傳統 Dijkstra 我們只紀錄 `distances[node]`，這題因為我們可以用不同價格和轉機次數到達相同節點，所以我們讓不同轉機次數的路線，在各自的平行時空競爭。
- 我們調整 `distances[node][stops]` 2D 陣列來紀錄在某個節點、不同轉機次數的不同價格，也就是 `k + 1` 種獨立狀態，每一個轉機次數都有專屬的擂台來競爭「最便宜的價格」
    - 到達節點 C 且轉機 1 次的票價，跟到達節點 C 且轉機 2 次的票價，本來就不該互相覆蓋，它們是完全獨立的狀態。
    - 之前我自己寫過一種紀錄方式 `states: Array(n) { (price to stops) }` 這樣是不對的，這樣只有維護一個節點的單一目前最佳狀態，然而，到達同一個節點可能有多種「有效」的可能：(price 高、stop 低) vs (price 低、stop 高) 這些都算是有效的路徑，都需要儲存而且去探索下去。使用 2D 陣列 `distances[node][stops]`，等於是為每一個轉擊次數都開了一個專屬的位子，讓所有有潛力的路線都能活下來繼續探索。

```kotlin
private data class FlightState(val node: Int, val price: Int, val stops: Int)

fun findCheapestPrice(n: Int, flights: Array<IntArray>, src: Int, dst: Int, k: Int): Int {
    val graph = buildGraph(n, flights)
    val states = Array(n) { IntArray(k + 2) { Int.MAX_VALUE } } // states[node][stops] and `k + 1` stops (1-based index)
    val heap = PriorityQueue(compareBy<FlightState> { it.price }.thenBy { it.stops })

    heap.add(FlightState(src, 0, 0))
    states[src][0] = 0
    while (heap.isNotEmpty()) {
        
        val (node, price, stops) = heap.poll()
        // Skip stale state: More expensive and same or more stops; or hits the total stops limitation 
        // Stale: 又貴、步數又多
        if ((price > states[node][stops]) || stops > k + 1) continue
        // Reach the destination
        if (node == dst) return price

        for ((adj, adjPrice) in graph[node]) {
            val nextPrice = price + adjPrice
            val nextStops = stops + 1
            if (nextStops > k + 1) continue

            // Relax: We have lower price of the same stop.
            // In general, we can relax as long as we have either
            // 1. Lower price regardless the number of stops
            // 2. Lower number of stops
            if (nextPrice < states[adj][nextStops]) {
                heap.add(FlightState(adj, nextPrice, nextStops))
                states[adj][nextStops] = nextPrice
            }
        }
    }
    return -1
}

private fun buildGraph(n: Int, flights: Array<IntArray>): Array<MutableList<Pair<Int, Int>>> {
    val adjList = Array(n) { mutableListOf<Pair<Int, Int>>() }
    for ((from, to, price) in flights) {
        adjList[from].add(to to price)
    }
    return adjList
}
```

### 1D 陣列優化 (Lazy Dijkstra)
我們利用 Min-Heap 出列的「價格單調遞增」特性，可以把 2D 狀態空間壓縮成 1D 陣列，1D 魔法能成立的唯一前提，是因為 Min-Heap 保證了「先彈出來的，價格一定最便宜」，彈出來的 Cost 絕對只會越來越貴。

想像一下你對同一個節點 `C` 記錄了以下歷史：
1. 第一次彈出：100 元，轉 5 次。
2. 第二次彈出：150 元，轉 3 次。
3. 第三次彈出：200 元，轉 1 次。

> 我們將「尋找最便宜」的任務全權委託給 Min-Heap，這賦予了我們一個強大的數學保證：**從 Heap 彈出同一個節點的順序，其價格絕對是遞增的（越來越貴）**。

如果用 2D 陣列，這三筆資料都會被完整存下來。 但仔細思考，因為未來的路線一定比 200 元更貴，我們**唯一會讓它通關的理由，是它的轉機次數必須更優，也就是必須少於目前看到的最少次數（也就是 1 次）**。因此，我們根本不需要記住前面那些 100 元、150 元是幾次，我們**只需要記住全域的「歷史最少轉機次數 (`minStops`)」即可**！

只要新進來的路徑，Stops 沒有打破這個歷史最低紀錄，加上它的 Cost 又一定比歷史紀錄貴，那就是毫無價值的垃圾，直接丟掉。只要它打破了歷史最少轉機紀錄（例如變 0 次），我們就把 `minStops` 往下更新。

然而，這樣的機制全部仰賴「先談出來的路徑，價格一定是最便宜的」，也就是我們需要等 pop 的階段才知道結果，這就是典型的 *Lazy Dijkstra*:
- 1D 寫法中，我們為了省空間，**放棄記錄最低花費，全權委託 Heap 來幫我們把關價格**。既然你把「價格排序」的工作交給了 Heap，你就必須「讓子彈飛」，等到資料從 Heap 彈出（排序完成）的那一刻，才能根據次數進行正確的生殺大權判斷。
- Push 階段只要轉機次數合法，就無腦全收；一切的過濾與更新，都交給 Pop 階段。

> 相同概念: [743. Network Delay Time](../leetcode/743.network-delay-time.md#lazy-dijkstra-visited-set)

```kotlin
// 狀態綁定：節點、累積花費、累積轉機次數
private data class FlightState(val node: Int, val price: Int, val stops: Int)

fun findCheapestPrice(n: Int, flights: Array<IntArray>, src: Int, dst: Int, k: Int): Int {
    // 1. 建立 Adjacency List
    val graph = Array(n) { mutableListOf<Pair<Int, Int>>() }
    for ((u, v, price) in flights) {
        graph[u].add(v to price)
    }

    // 2. 1D 防呆陣列：只記錄「歷史最少轉機次數」，初始化為無限大
    val minStops = IntArray(n) { Int.MAX_VALUE }
    
    // 3. Min-Heap：以價格為主排序，步數為輔 (Tie-breaker 優化)
    val heap = PriorityQueue(compareBy<FlightState> { it.price }.thenBy { it.stops })
    heap.add(FlightState(src, 0, 0))

    // 4. Lazy Dijkstra 擴展
    while (heap.isNotEmpty()) {
        val (node, price, stops) = heap.poll()

        // 【Pop 階段過濾】：因為價格一定越來越貴，步數必須創新低才有價值
        // k 次中轉 = 最多搭 k + 1 次飛機，所以 stops > k + 1 也是不合法的
        if (stops >= minStops[node] || stops > k + 1) continue
        
        // 第一次彈出終點，即為全域最便宜且合法的解
        if (node == dst) return price

        // 【Pop 階段更新】：確認存活，將門檻提高
        minStops[node] = stops

        // 【Push 階段】：不做狀態過濾，只要不超標就無腦全收，讓子彈飛
        for ((adj, adjPrice) in graph[node]) {
            val nextStops = stops + 1
            if (nextStops > k + 1) continue
            
            heap.add(FlightState(adj, price + adjPrice, nextStops))
        }
    }
    return -1
}
```

### 心法總結
- **2D 陣列**：可以在 Push 階段 (迴圈內) 做檢查與更新，因為每個轉機次數都有獨立的格子，不會互相誤殺，能提早剪枝減少 Heap 大小。
- **1D 陣列**：**必須**在 Pop 階段做檢查與更新。我們必須借助 Heap 排序完的「價格單調性」，才能用一個維度完美處理兩個維度的資訊。

這類「延遲到 Pop 階段更新 (Lazy Dijkstra)」的技巧，是解決圖論中 多目標最佳化 (Multi-Objective Optimization) 或是 帶條件限制的最短路徑 (Constrained Shortest Path) 的通用神兵利器。

只要題目的本質是「兩個維度在互相拉扯（例如：要便宜就花時間，要快就得砸錢）」，你都可以用同一個第一性原理：**把主目標交給 Heap 排序，把副限制交給 Pop 階段的 1D 陣列來防呆。**

At most `k` stops (as transfer stops) means that we have to go to `k + 1` stops to destination, we might go without any transfer stop, so we iterate from `0` to `k + 1` stops to find the cheapest cost. (`0` means that we're at source and can't go to anywhere, `1` means that we can go from source to destination without any transfer stop)

We can use dynamic programming to solve this problem, suppose `dp[t][j]` represents that we go by `t` stops to `j` stop, then we can transit the state from the minimum of all `dp[t - 1][i]` for all `i` can reach `j`

```js
// Previous to current
              [x] --> 
              [y] --> [j]      
              [z] --> 
// Stops
            t - 1      t

// Find the minimum among dp[t - 1][i] + cost(i, j)
min(dp[t - 1][i] + cost(i, j)) = dp[t][j]
```

Then, we have to find the minimum amoung `t = 1 to k + 1` of `dp[t][destination]` as answer.

```kotlin
fun findCheapestPrice(n: Int, flights: Array<IntArray>, src: Int, dst: Int, k: Int): Int {
    val infinite = Int.MAX_VALUE / 2
    val dp = Array(k + 2) { _ -> IntArray(n) { _ -> infinite } }
    // Base case, for 0 stops, the only destination we can reach is the source.
    dp[0][src] = 0

    for (t in 1..k + 1) {
        for (flight in flights) {
            val source = flight[0]
            val destination = flight[1]
            val cost = flight[2]
            dp[t][destination] = min(dp[t][destination], dp[t - 1][source] + cost)
        }
    }

    var result = infinite
    for (t in 1..k + 1) {
        result = min(result, dp[t][dst])
    }
    return if (result == infinite) -1 else result
}

// Or equivalent

fun findCheapestPrice(n: Int, flights: Array<IntArray>, src: Int, dst: Int, k: Int): Int {
    val infinite = Int.MAX_VALUE / 2
    val dp = Array(k + 1) { _ -> IntArray(n) { _ -> infinite } }
    
    // k is 0, the destination we can reach without any transfer stops is from `src`
    for (flight in flights) {
        val source = flight[0]
        val destination = flight[1]
        val cost = flight[2]
        if (source == src)
            dp[0][destination] = cost
    }

    for (t in 1..k) {
        for (flight in flights) {
            val source = flight[0]
            val destination = flight[1]
            val cost = flight[2]
            dp[t][destination] = min(dp[t][destination], dp[t - 1][source] + cost)
        }
    }

    var result = infinite
    for (t in 0..k) {
        result = min(result, dp[t][dst])
    }
    return if (result == infinite) -1 else result
}
```
