# [2466. Count Ways To Build Good Strings](https://leetcode.com/problems/count-ways-to-build-good-strings/)

## Key Insights
Building process (bottom-up from empty string):
```
- empty
   - 0
      - 00
         - 000
         - 0011
      - 011
        - ... // append 0
        - ... // append 11
   - 11
      - 110
      - 1111
```
For each string, we can either append `zero` number of `0`s or `one` number of `1`s. To count the dififerent good strings, the physical string itself is irrelevant, the only thing that matters is its **length**. We increase the length by `zero` or `one` when appending them for each string.

Given a length `i`, we can either append or remove `zero` (or `one`):
```js
_, _, _, _, i, _, _, _
   |--------|--------|
   i-zero            i+zero
```
- Remove `zero` from it, and count the number of good strings of length `i - zero`, `count[i]` comes from `count[i - zero]`.
- Or, append `zero` to a good string of length `i + zero`, `count[i + zero]` comes from `count[i]`.

> Same logic applies to `one` as well.

### Pitfall: How to generate the **different** good string?
I got stuck on how to generate the distinct good strings. The explanation is following:

Each time, we either append `zero` or `one` to a good string. Think back to [Climbing Stairs](../leetcode/70.climbing-stairs.md), because the two operations (taking 1 or 2 steps) are completely distinct, every unique sequence of operations automatically creates a unique path. Appending `zero` and `one` are distinct building operations, any unique path of operations will result in a distinct string.

### Why Greedy fails?
Greedy algorithms make localized "best" choices. However, this problem does not ask for the longest string, shortest string, or maximum elements. It asks for the total count of all valid permutations. A greedy approach abandons branches to isolate a single path, making it impossible to sum all combinatorial possibilities.

## Top-Down DP
Let `topDown(i)` be the number of good strings of length `i`. For each length `i`, we can either:
- Append `zero` to a good string of length `i - zero`, which contributes `topDown(i - zero)` ways.
- Append `one` to a good string of length `i - one`, which contributes `topDown(i - one)` ways.

And base case is when length is `0`, there is exactly 1 good string (empty).

```js
Length: 4
                [4]
              /     \
         (-1)/       \(-2)
            /         \
          [3]         [2]
         /   \        /  \
      [2]     [1]   [1]  [0]
      / \     / \   / \  ^^^
    [1] [0] [0] [-1]  ...
        ^^^ ^^^
```

```kotlin
fun countGoodStrings(low: Int, high: Int, zero: Int, one: Int): Int {
    val n = high
    val memo = LongArray(n + 1) { -1L }
    var counts = 0L
    for (i in low..high) {
        counts += topDown(i, zero, one, memo)
        counts %= MOD
    }
    return counts.toInt()
}

private fun topDown(len: Int, zero: Int, one: Int, memo: LongArray): Long {
    if (len == 0) return 1L
    if (len < 0) return 0L
    if (memo[len] != -1L) return memo[len]
    memo[len] = (topDown(len - zero, zero, one, memo) + topDown(len - one, zero, one, memo)) % MOD
    return memo[len]
}
```
- **Time Complexity:** 
    - Without memoization: `O(2^n)` for the recursion tree, for each length `i`, we can either append `zero` or `one`, so the recursion tree has 2 branches, and the maximum depth of the recursion tree is `n`.
    - With memoization: `O(n)` for a single pass through the lengths, and each length is computed only once.
- **Space Complexity:** `O(n)` for the recursion stack and memoization table.

## Bottom-Up
Let `dp[i]` be the number of good strings of length `i`. For each length `i`, we can apply the same logic as top-down DP, and the base case is `dp[0] = 1` (empty string).

$$dp[i] = (dp[i - \text{zero}] + dp[i - \text{one}]) \bmod (10^9 + 7)$$

Please note that we build the DP table from `0` to `high`, and we only sum the counts from `low` to `high` at the end. We don't iterate from `low` to `high` to build the DP table at the length `i`.

```kotlin
fun bottomUp(low: Int, high: Int, zero: Int, one: Int): Int {
    val dp = LongArray(high + 1)
    dp[0] = 1
    for (l in 1..high) {
        if (l - zero >= 0) {
            dp[l] = (dp[l] + dp[l - zero]) % MOD
        }
        if (l - one >= 0) {
            dp[l] = (dp[l] + dp[l - one]) % MOD
        }
    }
    var count = 0L
    for (i in low..high) {
        count += dp[i]
        count %= MOD
    }
    return count.toInt()
}
```
- **Time Complexity:** `O(high)`.
- **Space Complexity:** `O(high)`.
