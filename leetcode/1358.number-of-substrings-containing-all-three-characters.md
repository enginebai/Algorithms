# [1358. Number of Substrings Containing All Three Characters](https://leetcode.com/problems/number-of-substrings-containing-all-three-characters/)

## Derivation

### Step 1: 抽象化 (Abstraction)

* **剝離故事：** 不要管 `a`, `b`, `c`。
* **幾何意義：** 字串的「子字串（Substring）」，本質上就是一維陣列上的一個**連續區間 $[L, R]$**。
* **等價轉換：** 我們的目標是找出所有滿足「特定條件（包含三種元素）」的 $[L, R]$ 區間總數。

### Step 2: 降維與暴力解 (Brute Force)

* **直觀窮舉：** 既然要找區間，最笨的方法就是窮舉所有的起點 $L$ 與終點 $R$。
1. 固定起點 $L = 0$。
2. 終點 $R$ 從 $L$ 開始往右掃描，每走一步就檢查一次 $[L, R]$ 區間內是否集齊了三種元素。
3. 如果找到了，就記錄下來。
4. $L$ 往右移一格，重複步驟 2。


* **時間複雜度：** $O(N^2)$ 的區間窮舉，加上檢查元素的成本。

### Step 3: 抓出效能瓶頸 (Bottleneck)

暴力解的致命傷在於「沒有從已知的成功中學習」，這裡我們用兩個 "What if" 挑戰來找出重複計算：

* **發現 1：有效性的單調擴張 (Monotonicity)**
    * *What if:* 當我固定 $L$，向右掃描到某個 $R$ 時，終於集齊了三種字元（$[L, R]$ 是合法的）。那麼 $[L, R+1]$, $[L, R+2]$ 一直到字串結尾 $[L, N-1]$，還需要檢查嗎？
    ```js
    _, _, _, _, _, _, _, _
          L        R        // valid
          L           R     // also valid
          L              R  // also valid
    ```
    * *本質：* 往合法的集合裡塞更多垃圾，它依然是合法的！所以只要找到**第一個**合法的 $R$，從 $R$ 到字串結尾的 $(N - R)$ 個子字串**全部都合法**，根本不用繼續往下掃描。

* **發現 2：雙指針的不可逆性 (Unidirectional)**
    * *What if:* 當我算完 $L$ 開頭的答案，將 $L$ 推進到 $L+1$ 時，我的 $R$ 需要像暴力解一樣退回到 $L+1$ 重新開始找嗎？
    * *本質：* 當 $L$ 往右縮減（失去了一個字元），這個區間只會變得「更缺乏」字元。為了再次集齊條件，$R$ 只能被迫**繼續往右走**去尋找新字元，絕對不可能往回頭走。

### Step 4: 武器庫映射 (Weapon of Choice)

結合 Step 3 的兩大發現：

1. 區間是連續的。
2. 左邊界 $L$ 與右邊界 $R$ 在整個生命週期中，都**只會單向往右移動，絕對不回頭**。

在演算法武器庫中，能完美對應「維護一段連續區間，且兩個邊界具備單向遞增特性」的資料結構，就是**滑動窗口（Sliding Window / Two Pointers）**。這就是為什麼你的直覺會呼喚出滑窗，因為它是由這道題目的「物理單調性」所決定的必然結果。

---

你的程式碼中，最精妙也最容易讓人卡住的地方是 `answer += left` 這一行。這行程式碼在「幾何與物理」上的計數意義是什麼嗎？

* **視角反轉 (Perspective Shift)：** 我的推導是「固定左邊界 $L$，向右看」，這在思維上直觀，但不好寫成單層迴圈。你的實作是「固定右邊界 $R$，向左看」，這完美契合了 `for (right in s.indices)` 這個事件驅動的設計。
* **物理對應 (Physical Mapping)：** 當你的 `right` 走到某個位置，這代表「時間點」。`while` 迴圈不斷把 `left` 往右推，直到窗口 `[left, right]` 剛好被破壞（變成無效）為止。
* **數學必然 (Mathematical Inevitability)：** 當 `while` 迴圈結束時，當下的 `left` 已經是無效邊界，這意味著 `[left - 1, right]` 是最後一個合法的極限短窗口。既然最短的都合法，那麼把左邊界繼續往外擴張到 `left - 2`, `left - 3`, 一直到 `0`，這些長窗口必定全部合法！從 `0` 到 `left - 1`，總共剛好就是 `left` 個起點。

這就是為什麼 `answer += left` 如此優雅，你不需要去算右邊剩多少，你只結算「以當前 $R$ 為結尾，能產生多少個合法的左起點」。這是一個非常高級的計數技巧！

```kotlin
fun numberOfSubstrings(s: String): Int {
    var left = 0
    val counts = IntArray(3)
    var answer = 0
    for (right in s.indices) {
        counts[s[right] - 'a']++
        while (counts.isOK()) {
            counts[s[left] - 'a']--
            left++
        }
        answer += left
    }
    return answer
}

private fun IntArray.isOK(): Boolean {
    for (i in this.indices) {
        if (this[i] <= 0) return false
    }
    return true
}
```
