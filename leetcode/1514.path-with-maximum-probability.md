# [1514. Path with Maximum Probability](https://leetcode.com/problems/path-with-maximum-probability/description/)

## Coding Derivation
- Abstraction: Since edge weights are `0 <= p <= 1`, multiplying probabilities makes the total probability strictly smaller. (e.g., `0.9 x 0.9 = 0.81 < 0.9`). As we traverse a path, the cost (*probability*) is monotonic (will always decrease). Therefore, the maximum probability path is the one with the **least number of edges**.
- Brute force: We can use DFS to traverse all paths from `start` to `end`, and keep track of the maximum probability.

```kotlin
private var maxProb = 0.0
private fun dfs(
    graph: Array<MutableList<EdgeProb>>,
    i: Int,
    end: Int,
    visited: BooleanArray,
    prob: Double,
    allProbs: MutableList<Double>
) {
    if (i == end) {
        maxProb = maxOf(maxProb, prob)
        return
    }
    if (visited[i]) return
    visited[i] = true
    for ((adj, adjProb) in graph[i]) {
        val nextProb = prob * adjProb
        dfs(graph, adj, end, visited, nextProb, allProbs)
    }
    visited[i] = false
}
```

> 時間複雜度 `O(V!)`，想像一個有 `V` 個節點的完全圖（每個節點都與其他所有節點相連），當你在尋找「所有可能路徑」並使用 `visited[i] = false` 進行 Backtracking 時：
>  - 從起點出發，你有 V - 1 個鄰居可以選擇。
>  - 走到下一個節點後，扣除起點，你有 V - 2 個鄰居可以選擇。
>  - 再走到下一個節點，你有 V - 3 個選擇...
> 
> 依此類推，總共探索的路徑數量（遞迴樹的葉節點數量）會逼近 `(V - 1) * (V - 2) * (V - 3) * ... * 1`。

- Bottleneck analysis: Since we are searching the path with the maximal probability, it might a waste to visit the path with smaller probability. For example, we have discovered a path `A → B → C → T` has `p = 0.8`, so there is no need to check the path `A → B → D → E → T` with `p = 0.6`.
- Pattern recognition: 
    - We prioritize to explore the larger probability first.
    - Because multiplying by a `p <= 1` can never increase the probability, it's physically impossible to find a "better" path to a node later by traversing a longer path. Therefore, the first time we reach a node, we have found the maximum probability path to that node.
    - Therefore, the maximum probability path is the one with the **least number of edges**. This is a **shortest path problem**.
    - And we must guarantee that **the first time** we lock in a path to a node, it's the absolute best path.
    -> Dijkstra

> Q: Why Dijkstra? The Trigger: You are given a graph, a starting node, a target node, and asked to find the "best" path based on weights.

## Dijkstra
```kotlin
private data class EdgeProb(val to: Int, val prob: Double)

fun dijkstra(
    n: Int,
    edges: Array<IntArray>,
    succProb: DoubleArray,
    start_node: Int,
    end_node: Int
): Double {
    val graph = buildGraph(n, edges, succProb)
    val probArray = DoubleArray(n)
    val minHeap = PriorityQueue(compareByDescending<EdgeProb> { it.prob })
    minHeap.add(EdgeProb(start_node, 1.0))
    probArray[start_node] = 1.0
    while (minHeap.isNotEmpty()) {
        val (node, prob) = minHeap.poll()
        if (prob < probArray[node]) continue
        if (node == end_node) return prob
        for ((adj, adjProb) in graph[node]) {
            if (probArray[adj] < prob * adjProb) {
                probArray[adj] = prob * adjProb
                minHeap.add(EdgeProb(adj, probArray[adj]))
            }
        }
    }
    return 0.0
}

private fun buildGraph(n: Int, edges: Array<IntArray>, succProb: DoubleArray): Array<MutableList<EdgeProb>> {
    val adjList = Array(n) { mutableListOf<EdgeProb>() }
    for (i in edges.indices) {
        val (a, b) = edges[i]
        val prob = succProb[i]
        adjList[a].add(EdgeProb(b, prob))
        adjList[b].add(EdgeProb(a, prob))
    }
    return adjList
}
```

> Q: 為什麼 Dijkstra 處理無向圖時，不需要額外用 visited 陣列防呆？
這個問題非常核心。答案在於 「距離/機率陣列（probArray）加上單調性」本身就完美兼任了防呆機制。

因為 Dijkstra 的數學前提是單調遞減（或成本單調遞增），只要你在圖裡面繞圈圈、走回頭路，算出來的成本「必定比以前更差」。既然更差，就會被 probArray 的檢查直接擋下來，永遠不會被加進 Queue 裡面。因此，無向圖的環狀結構會被演算法自然地斬斷，不需要額外的 visited 陣列。

## Shortest Path Faster Algorithm (SPFA)

Since the weight of each edges is `[0, 1]`, the probability of the path will be the same or less than the previous path. We're finding the maximum probability, so we're actually finding the shortest path. We can use BFS to traverse the graph and update the probability of each node.

```kotlin
data class GraphNode(
    val toNode: Int, // indegree node
    val prob: Double // probability of the indegree edge
)

class Solution {
    fun maxProbability(n: Int, edges: Array<IntArray>, succProb: DoubleArray, start_node: Int, end_node: Int): Double {
        val graph = buildGraph(edges, succProb)
        val prob = DoubleArray(n)

        // Remember to set the start node to 1.0
        prob[start_node] = 1.0
        val queue = ArrayDeque<Int>()
        queue.addLast(start_node)
        while (queue.isNotEmpty()) {
            val node = queue.removeFirst()
            graph[node]?.forEach { adj ->
                if (prob[adj.toNode] < prob[node] * adj.prob) {
                    prob[adj.toNode] = prob[node] * adj.prob
                    queue.addLast(adj.toNode)
                }
            }
        }
        return prob[end_node]
    }

    private fun buildGraph(edges: Array<IntArray>, succProb: DoubleArray): HashMap<Int, HashSet<GraphNode>> {
        val graph = HashMap<Int, HashSet<GraphNode>>()
        for (i in 0 until edges.size) {
            val edge = edges[i]
            val prob = succProb[i]
            if (!graph.containsKey(edge[0])) graph[edge[0]] = HashSet<GraphNode>()
            if (!graph.containsKey(edge[1])) graph[edge[1]] = HashSet<GraphNode>()

            graph[edge[0]]!!.add(GraphNode(edge[1], prob))
            graph[edge[1]]!!.add(GraphNode(edge[0], prob))
        }
        return graph
    }
}
```
