# [3613. Minimize Maximum Component Cost](https://leetcode.com/problems/minimize-maximum-component-cost/)

### Requirements
- Undirected weighted graph, `n` nodes, `1 ≤ k ≤ n`. The input graph is connected.
- Free to remove edges so that total number of component is at most `k`.
- The **cost** of a component is defined as the **maximum** edge weight in that component. If a component has no edges, its cost is 0.
- Goals: Find the minimum of the maximum cost.

- **二分搜的等價驗證 (Filtering)：** 當你猜測最大成本天花板是 `X` 時，你的驗證方式不是去「拆」原圖，而是準備 *N* 個孤立的節點，然後巡視原本的那份關係清單。**只要邊的權重 ≤*X*，你就把它接上去**。全部接完之後，算算看整張圖剩下幾個元件。

- **單調性的保證 (Monotonicity)：** 你接上的邊越多（`X` 設得越大），節點之間越容易連通，元件數量就會越少。如果最後算出來的元件數 ≤*k*，代表這個 `X` 已經足夠寬鬆能達成目標，你就可以放心地把搜尋範圍縮小，去左半邊尋找有沒有更小的 `X`。

## Derivation


### Abstraction

* **剝離故事：** 忘掉「移除（Remove）」與「成本（Cost）」。
* **數學本質：** 我們有一個包含 $N$ 個節點的空圖，以及一份邊的清單 $E$（包含權重）。我們要定義一個「權重天花板 $X$」。
* **等價轉換：** 我們的目標是：找到一個**最小的 $X$**，使得我們「只使用權重 $\le X$ 的邊」來建圖時，整張圖的連通元件數量能夠 $\le k$。

### Brute Force

* **放寬限制：** 既然我們要找「最小的 $X$」，最直觀、最不用動腦的暴力解是什麼？就是**線性掃描（Linear Search）猜答案**。
* **暴力解輪廓：** 假設邊的權重範圍是 $1$ 到 $10^9$。
1. 從 $X = 1$ 開始猜。
2. 掃描所有邊，只把 $\le X$ 的邊拿來建圖。
3. 跑一次 DFS/BFS 算元件數量。
4. 如果元件數 $> k$（不合格），就把 $X$ 加 $1$，清空整張圖，回到步驟 2 重新來過。
5. 直到某個 $X$ 第一次讓元件數 $\le k$，這個 $X$ 就是答案。


* **時間複雜度：** $O(\text{MaxWeight} \times (V + E))$。這個作法在邏輯上絕對正確，但只要權重範圍很大，必定 Time Out。

### Bottleneck Analysis

* **發現重複計算：** 暴力解的致命傷在於「明知故問」的無效掃描。
* **What if 挑戰：** 如果我今天測試 $X = 1000$，發現元件數還是太多（$> k$）。那麼 $X = 999$ 或 $X = 1$ 有可能成功嗎？
絕對不可能！因為天花板越低，能用的邊越少，圖就越破碎，元件數只會**更多**。
* **找出數學特性：** 隨著 $X$ 的增加，連通元件的數量必定是「遞減或持平」的。這意味著，答案空間具有完美的**單調性（Monotonicity）**。線性掃描在一種「已排序、單調」的空間裡一步一步走，這就是最大的效能浪費。

### Pattern Recognition

現在，針對我們剛才找出的兩大問題，從武器庫抽出對應的解法：

1. **針對「單調空間的無效掃描」：** 拿出 **Binary Search (二分搜尋)**。我們不需要從 $1$ 走到 $10^9$，而是直接切一半猜，把 $O(W)$ 的猜測次數瞬間降維成 $O(\log W)$。
2. **針對「每次都要重新建圖跑 DFS 算元件數」：** 拿出 **Union Find (併查集)**。
一開始元件數為 $N$。遇到一條 $\le X$ 的邊，就把兩個節點 Union 起來。如果成功合併，元件數就 `-1`。掃描完一次邊，我們就能以極低的成本（幾乎 $O(1)$）瞬間知道當下剩幾個元件，連 Graph 都不用建。

**終極結合：** 外層用二分搜尋選定 $X$，內層用 Union Find 過濾並計算元件數。時間複雜度大幅壓縮至 $O(\log(\text{MaxWeight}) \times E \alpha(V))$。

透過這完整的四步，你的「二分搜」就不再是憑空跳出來的靈感，而是為了解決「暴力解的線性掃描效能瓶頸」所做出的必然架構選型。

```kotlin
fun minCost(n: Int, edges: Array<IntArray>, k: Int): Int {
    if (n <= k) return 0
    // Sorted by weight
    edges.sortBy { it[2] }

    var left = 0
    var right = edges.size - 1
    while (left <= right) {
        val middle = left + (right - left) / 2
        val maxWeight = edges[middle][2]
        if (isFeasible(n, edges, k, maxWeight)) {
            right = middle - 1
        } else {
            left = middle + 1
        }
    }
    return if (left !in 0 until edges.size) -1 else edges[left][2]
}

private fun isFeasible(n: Int, edges: Array<IntArray>, k: Int, weightUpperBound: Int): Boolean {
    val graph = buildGraph(n, edges, weightUpperBound)
    val visited = BooleanArray(n)
    var componentsCount = 0
    for (i in 0 until n) {
        if (visited[i].not()) {
            dfs(graph, i, visited)
            componentsCount++
        }
    }
    return componentsCount <= k
}

private fun dfs(graph: Array<MutableList<Int>>, i: Int, visited: BooleanArray) {
    if (visited[i]) return
    visited[i] = true
    for (adj in graph[i]) {
        dfs(graph, adj, visited)
    }
}

private fun buildGraph(n: Int, edges: Array<IntArray>, maxWeight: Int): Array<MutableList<Int>> {
    val graph = Array(n) { mutableListOf<Int>() }
    for ((u, v, w) in edges) {
        if (maxWeight < w) break
        graph[u].add(v)
        graph[v].add(u)
    }
    return graph
}
```
