# [2684. Maximum Number of Moves in a Grid](https://leetcode.com/problems/maximum-number-of-moves-in-a-grid/description/)

## Key Insights
There are some key constraints in this problem:
- For each cell `(i, j)`, we can move to right-up (`i - 1, j + 1`), right (`i, j + 1`), or right-down (`i + 1, j + 1`) if the value of the next cell > current cell.
```js
         (i - 1, j + 1)       
       /                         
(i, j) - (i,   , j + 1)
       \
         (i + 1, j + 1)
```
- We can start from the any cell in the first column only, we can't start from any other column.

## BFS
We can traverse the grid using level-by-level BFS from the first column, then enqueue the next valid cells (not visited and `current < next`) to expand the move.

```kotlin
fun maxMoves(grid: Array<IntArray>): Int {
    val directions = intArrayOf(-1, 0, 1)
    val m = grid.size
    val n = grid[0].size
    val queue = ArrayDeque<Pair<Int, Int>>()
    val visited = Array(m) { BooleanArray(n) }
    var maxMoves = 0
    for (r in 0 until m) {
        queue.addLast(r to 0)
        visited[r][0] = true
    }
    while (queue.isNotEmpty()) {
        val size = queue.size
        repeat (size) {
            val (row, col) = queue.removeFirst()
            if (col == n - 1) return n - 1

            for (d in directions) {
                val newRow = row + d
                val newCol = col + 1
                if (newRow !in 0 until m || newCol !in 0 until n) continue
                if (visited[newRow][newCol]) continue
                if (grid[row][col] >= grid[newRow][newCol]) continue

                queue.addLast(newRow to newCol)
                visited[newRow][newCol] = true
            }
        }
        maxMoves++
    }
    return maxMoves - 1
}
```

## Top-Down DP
We start from all the cells in the first column, then go through the 3 possible moves if (current < next), and find the maximum number of moves we can make.
 
There will be some overlapping subproblems, for example, when we calculate `f(A)`, we will calculate `f(Y)` as subproblem; when we calculate `f(B)` and `f(C)`, there are the same subproblem `f(Y)` again. So we can use memoization to store the result of each cell.
```js
A  
  \
B --> Y
  /
C 
```

```kotlin
fun maxMoves(grid: Array<IntArray>): Int {
    val m = grid.size
    val n = grid[0].size
    var maxMoves = 0
    val memo = Array(m) { IntArray(n) { -1 }}
    for (r in 0 until m) {
        maxMoves = maxOf(maxMoves, moves(grid, r, 0, memo))
    }
    return maxMoves
}

private fun moves(grid: Array<IntArray>, row: Int, col: Int, memo: Array<IntArray>): Int {
    if (memo[row][col] != -1) return memo[row][col]
    val m = grid.size
    val n = grid[0].size
    var maxMoves = 0
    for (d in directions) {
        val newRow = row + d
        val newCol = col + 1
        if (newRow !in 0 until m || newCol !in 0 until n) continue
        if (grid[row][col] >= grid[newRow][newCol]) continue
        maxMoves = maxOf(maxMoves, 1 + moves(grid, newRow, newCol, memo))
    }
    memo[row][col] = maxMoves
    return maxMoves
}
```

### Pitfall
My initial solution was to use DFS from the last column, like the typical grid DP problem.

```js
(i - 1, j - 1)
               \
(i    , j - 1) - (i, j)
               /
(i + 1, j - 1) 
```

But it will fail from the case `[1, 2, 0]`, my solution will start from `f(0)` then stop since `2 > 0`, but there is a valid path from `1 -> 2`

> 在這題中，「起點是固定的（必定是 Column 0），但終點是未知的」，可是我的解法卻是「終點是固定的，起點是未知的」。正向搜尋才符合題目的原始定義。

```kotlin
private var maxMoves = 0
fun maxMoves(grid: Array<IntArray>): Int {
    val m = grid.size
    val n = grid[0].size
    for (r in 0 until m) {
        // Start from the last column: `n - 1`, and go down to the previous column.
        moves(grid, r, n - 1)
    }
    return maxMoves
}

private fun moves(grid: Array<IntArray>, i: Int, j: Int): Int {
    if (j == 0) return 0
    val current = grid[i][j]
    val topLeft = if (i > 0 && grid[i - 1][j - 1] < current) moves(grid, i - 1, j - 1) else -1
    val left = if (grid[i][j - 1] < current) moves(grid, i, j - 1) else -1
    val bottomLeft = if (i + 1 < grid.size && grid[i + 1][j - 1] < current) moves(grid, i + 1, j - 1) else -1

    var nextMoves = -1
    if (topLeft != -1) nextMoves = maxOf(nextMoves, topLeft + 1)
    if (left != -1) nextMoves = maxOf(nextMoves, left + 1)
    if (bottomLeft != -1) nextMoves = maxOf(nextMoves, bottomLeft + 1)
    maxMoves = maxOf(maxMoves, nextMoves)
    return nextMoves
}
```

## Bottom-Up DP
We can build up a 2D array to store the maximum number of moves we can make from cell `(i, j)`, and base case is the first column which is `0` as starting point. Then we can iterate from left to right, and for each cell `(i, j)`, we can check the 3 possible moves and update the answer.

In the correct version, the `dp[i][j]` means:

> The maximum moves needed to reach cell `(i, j)` from some valid starting cell in first column.

So two invariants are required:
1. Only the first column starts as reachable: `move[r][c] = 0`. (Base case)
2. Every other cell must start as unreachable: `move[r][c] = -1`. (Unreachable)

```kotlin
private fun bottomUp(grid: Array<IntArray>): Int {
    val m = grid.size
    val n = grid[0].size
    val moves = Array(m) { IntArray(n) { -1 } }
    // Base case
    for (r in 0 until m) {
        moves[r][0] = 0
    }
    for (c in 0 until n - 1) {
        for (r in 0 until m) {
            if (moves[r][c] == -1) continue // We have to skip the invalid path.

            if (r > 0 && grid[r][c] < grid[r - 1][c + 1]) {
                moves[r - 1][c + 1] = maxOf(
                    moves[r - 1][c + 1],
                    moves[r][c] + 1
                )
            }
            if (grid[r][c] < grid[r][c + 1]) {
                moves[r][c + 1] = maxOf(
                    moves[r][c + 1],
                    moves[r][c] + 1
                )
            }
            if (r + 1 < m && grid[r][c] < grid[r + 1][c + 1]) {
                moves[r + 1][c + 1] = maxOf(
                    moves[r + 1][c + 1],
                    moves[r][c] + 1
                )
            }
        }
    }
    var maxMoves = 0
    for (r in 0 until m) {
        for (c in 0 until n) {
            maxMoves = maxOf(maxMoves, moves[r][c])
        }
    }
    return maxMoves
}
```

### Pitfall
The DP table initalizes every cell to `0`, so unreachable cells look the same as reachable starting cells. It allows us to start a path from non-first column, which violates the requirement (start from first column only). There is no way to "detect the invalid path" at all. -> Initialize to `-1`.

> Correct bottom-up DP propagates only from reachable cells starting at column 0; the Pitfall version accidentally treats every cell as a possible starting point.

```kotlin
private fun bottomUp(grid: Array<IntArray>): Int {
    val m = grid.size
    val n = grid[0].size
    val moves = Array(m) { IntArray(n) }
    // Base case
    for (r in 0 until m) {
        moves[r][0] = 0
    }
    for (c in 1 until n - 1) {
        for (r in 0 until m) {
            if (r > 0 && grid[r][c] < grid[r - 1][c + 1]) {
                moves[r - 1][c + 1] = maxOf(
                    moves[r - 1][c + 1],
                    moves[r][c] + 1
                )
            }
            if (grid[r][c] < grid[r][c + 1]) {
                moves[r][c + 1] = maxOf(
                    moves[r][c + 1],
                    moves[r][c] + 1
                )
            }
            if (r + 1 < m && grid[r][c] < grid[r + 1][c + 1]) {
                moves[r + 1][c + 1] = maxOf(
                    moves[r + 1][c + 1],
                    moves[r][c] + 1
                )
            }
        }
    }
    var maxMoves = 0
    for (r in 0 until m) {
        for (c in 0 until n) {
            maxMoves = maxOf(maxMoves, moves[r][c])
        }
    }
    return maxMoves
}
```

## Bottom-Up DP (Space Optimization)
We can use two columns to replace the 2D array, since we only need the previous column to calculate the current column. The space complexity will be reduced from `O(m * n)` to `O(m)`.

```kotlin
private fun bottomUpSpaceOptimized(grid: Array<IntArray>): Int {
    val m = grid.size
    val n = grid[0].size
    val moves = Array(m) { IntArray(2) { -1 } }
    var maxMoves = 0
    for (r in 0 until m) {
        moves[r][0] = 0
    }
    for (c in 0 until n - 1) {
        for (r in 0 until m) {
            if (moves[r][0] == -1) continue
            for (d in directions) {
                val newRow = r + d
                if (newRow !in 0 until m) continue
                if (grid[r][c] >= grid[newRow][c + 1]) continue
                moves[newRow][1] = maxOf(moves[newRow][1], moves[r][0] + 1)
                maxMoves = maxOf(maxMoves, moves[newRow][1])
            }
        }
        // Roll the columns, remember to reset the new column to default value `-1`.
        for (r in 0 until m) {
            moves[r][0] = moves[r][1]
            moves[r][1] = -1 // The key, see below.
        }
    }
    return maxMoves
}
```

### Why to set `-1`?
When we move to the next column, we "roll" the current column to the previous column, and we need to reset the current column to `-1` (unreachable) for the next iteration. If we don't reset it, it will keep the value from the previous iteration, which may cause incorrect results.

For example:
```js
[0  -1] // Initial state (base case)

// First iteration:
10, 20,  5, 30
[0,  1] // Update next column to 1 since 10 < 20
[1 <-1] // Roll to previous column, but we don't reset.

// Next iteration:
10, 20,  5, 30
    [1,  1] // 20 > 5, we don't update the next column.
    [1 <-1] // Roll

// Next iteration:
10, 20,  5, 30
        [1,  2] // Update next column since 5 < 30
```

The answer is 2, which is incorrect, it evaluates the wrong path `10 -> 20 -> 30`, the correct path `10 -> 20 -> x` breaks at `5`, but we don't reset the current column to `-1`, so it still thinks `5` is reachable, which is wrong.
