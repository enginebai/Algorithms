# [2086. Minimum Number of Food Buckets to Feed the Hamsters](https://leetcode.com/problems/minimum-number-of-food-buckets-to-feed-the-hamsters/description/)

## Greedy
這題我初步的想法是這樣：
1. 找到所有 `H`，在他的左邊跟右邊空格都放 Feed (feed count+1)。同時排除不可能的情況，就是有 `HHH` 這樣的情況出現。
2. 然後再針對每個 Feed 去看能不能降低數量同時也還能滿足 `H` 都有餵到。

可是這樣的做法會出現這種情況，當你嘗試拔掉一個飼料桶時，你會引發骨牌效應：「拔掉這個，左邊的倉鼠會不會餓死？如果不拔，右邊的倉鼠是不是重複餵了？」這會直接把時間複雜度拖進死胡同。

我們來進行這題的第一性原理重構。請把思維從「全局先放滿」切換成「極度懶惰且貪婪的順向掃描 (Lazy & Greedy)」。
1. 假設我們從左走到右，我們「非常懶惰」只有在真正需要餵食的時候才為，也就是看到一隻「確定沒有被餵食的倉鼠」時才放飼料桶。
2. 針對目前要餵食的倉鼠，我們應該放左邊還是右邊呢？
    - 左邊 `x, H`: 我們從左邊走過來，接下來的倉鼠只會在更右邊，所以放左邊只會餵飽當下這倉鼠。
    - 右邊 `H, x`: 放右邊會餵飽當下這倉鼠，也有機會餵飽下一隻倉鼠 `H, x, H`。(貪心)

```kotlin
const val FED = 'F'

fun minimumBuckets(h: String): Int {
    val n = h.length
    var lastFedIndex = -1
    var fedCount = 0
    for (i in h.indices) {
        if (h[i] == 'H') {
            // We have previous and fed by previous
            if (i > 0 && lastFedIndex == i - 1) continue

            // Not fed, then we try to put right or left or impossible
            if (i + 1 < n && h[i + 1] == '.') {
                lastFedIndex = i + 1
                fedCount++
            } else if (i - 1 >= 0 && h[i - 1] == '.') {
                lastFedIndex = i - 1
                fedCount++
            } else {
                return -1
            }
        }
    }
    return fedCount
}
```
