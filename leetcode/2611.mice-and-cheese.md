# [2611. Mice and Cheese](https://leetcode.com/problems/mice-and-cheese/)

這是我原始的思路：

> 我會用 A, B 代表老鼠 1, 2 避免混淆，這題我所理解是 A 要拿 `k` 個物件，B 要拿剩下的 `n - k` 個物件，使得總分數是最大，物件被某個人拿走後就不能再拿了。A 要拿 `k` 個，B 要拿剩下 `n - k` 個，所以每個物件都會被拿走這樣才會盡可能拿到最大總和。那麼每個物件要嘛被 A 拿走或者 B 拿走，我們就看每個物件是誰拿走可以獲得比較多分 `reward1[i]` vs `reward2[i]` 就好。
>
> 因為我們要拿多分，所以我們就先把 A, B 分數排序，從大到小拿，如果 A, B 拿到的是同一個物件，兩個就比較分數，分數大的獲勝。如果是不同物件，而且都沒拿過，那我們就直接拿。

```kotlin
fun miceAndCheese(reward1: IntArray, reward2: IntArray, k: Int): Int {
    val n = reward1.size
    val heap1 = PriorityQueue(compareByDescending<Int> { reward1[it] })
    val heap2 = PriorityQueue(compareByDescending<Int> { reward2[it] })

    for (i in reward1.indices) {
        heap1.add(i)
        heap2.add(i)
    }
    val used = BooleanArray(n)
    var size1 = k
    var size2 = n - k
    var sum = 0
    while (size1 > 0 && size2 > 0) {
        var index1 = heap1.poll()
        var index2 = heap2.poll()
        if (index1 == index2) {
            used[index1] = true
            sum += if (reward1[index1] >= reward2[index2]) {
                size1--
                reward1[index1]
            } else {
                size2--
                reward2[index2]
            }
        } else {
            while (used[index1] && heap1.isNotEmpty()) index1 = heap1.poll()
            while (used[index2] && heap2.isNotEmpty()) index2 = heap2.poll()
            sum += reward1[index1]
            sum += reward2[index2]
            size1--
            size2--
            used[index1] = true
            used[index2] = true
        }
    }
    while (size1 > 0) {
        var index1 = heap1.poll()
        while (used[index1] && heap1.isNotEmpty()) index1 = heap1.poll()
        sum += reward1[index1]
        size1--
        used[index1] = true
    }
    while (size2 > 0) {
        var index2 = heap2.poll()
        while (used[index2] && heap2.isNotEmpty()) index2 = heap2.poll()
        sum += reward2[index2]
        size2--
        used[index2] = true
    }
    return sum
}
```

這個思路可以拆解成兩個假設：
1. 同個物件，誰拿的分數高就給誰拿。
2. 為了總分最大，從絕對分數高的開始拿。

這樣的思路在「無限物件」的時候是正確的，可是這題有數量的限制，A 只能拿 `k` 個，B 只能拿 `n - k` 個，因為名額有限，所以「單純比較大小」的策略就不一定是最優解，而是需要考量「妥協」。

我們來看一個失敗測資:
```js
k = 1
        0    1  // index
A = [1000, 100]
B = [ 999,  10]
```

照我的思路來看：
1. 將 A, B 分數排序，A 最高是 1000，B 最高是 999
2. A, B 搶「物件 0」，所以比較分數，拿高的，所以 A 拿 1000
3. 名額只有 1，所以 A 拿完了。
4. 剩下的物件只能塞給 B 拿 10。
5. 這樣總分是 1010。

但是如果我們換個方式分配：B 拿 999，A 拿 100，總分是 1099，這樣就比前面多了。

盲點在哪？「同一個位置的物件，要給 A 還是 B」在原始思路的「絕對高分」不一定是最優解，忽略了「選擇後的代價」。正確的思維不應是「這個物件給誰拿之後就能獲得絕對高分」，而是應該想「這個物件不給 A 拿反而給 B 拿後，實際上會失去幾分？」
- `index 0: [1000, 999]`，不給 A 拿，只給 B，那麼只會失去 1 分。
- `index 1: [100, 10]`，不給 A 拿，只給 B，那麼會失去 90 分。

既然 A 的名額非常珍貴（只有 `k` 個），A 就應該把名額用在「如果不給 A 拿，就會虧超多」的物件上（也就是物件 1），而不是去跟 B 搶那個「大家拿都差不多高分」的物件 0。所以，決定物件歸屬的關鍵，從來都不是 `reward1[i]` 絕對值有多大，而是 `reward1[i] - reward2[i]` 的「不可取代性」有多高。這就是你的思路中，需要被翻轉的最後一塊拼圖。

> K largest `A[i] - B[i]`.

```kotlin
fun miceAndCheese(reward1: IntArray, reward2: IntArray, k: Int): Int {
    val n = reward1.size
    // Original index and its differences
    val diff = Array<Pair<Int, Int>>(n) { it to (reward1[it] - reward2[it]) }
    diff.sortByDescending { it.second } // Sort by differences

    var sum = 0
    var i = 0
    for (i in 0 until n) {
        val index = diff[i].first
        if (i < k) { // Assign the first k items to A
            sum += reward1[index]
        } else { // Assign the remaining n - k items to B
            sum += reward2[index]
        }
    }
    return sum
}
```

這題還有一個更容易理解的思路：
- 我們都先給 B，所以得分是 `sum(reward2[i])`，這是一個保底分數。
- 但是 A 必須拿 `k` 個物件，代表我們必須要從 B 搶走 `k` 個物件。
- 當 A 搶走 `i` 物件時，總分變化是 `- reward2[i] + reward1[i]` (B 扣除，A 增加)，淨利潤是 `reward1[i] - reward2[i]`。
- A 必須要搶走淨利潤最大的前 `k` 個物件。
