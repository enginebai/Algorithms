# [1631. Path With Minimum Effort](https://leetcode.com/problems/path-with-minimum-effort/description/)

## Derivation
### Abstraction

- Find all the paths from top-left to bottom-right and its efforts, pick the minimum one.

- The “effort” of a path is the maximum absolute difference between two adjacent nodes in that path.

### Simplification

1x1, 1x2, 2x1, 2x2

```kotlin
A, B    1, 3
C, D    2, 7

dfs(A, 0)
  dfs(B, 2)
    dfs(D, 4) = 4 (min)
  dfs(C, 1)
    dfs(D, 5) = 5
```

### Brute Force

1. Run DFS or BFS starting from top-left, update the effort during traversal, stop until reaching the bottom-right, add the current effort to effort list.

2. Then find the minimum from effort list.

```kotlin
fun bruteForce(heights: Array<IntArray>): Int {
    val m = heights.size
    val n = heights[0].size
    val allEfforts = mutableListOf<Int>()
    val visited = Array(m) { BooleanArray(n) }
    dfs(heights, 0, 0, visited, 0, allEfforts)
    return allEfforts.min()
}

private fun dfs(heights: Array<IntArray>, row: Int, col: Int, visited: Array<BooleanArray>, currentEffort: Int, allEfforts: MutableList<Int>) {
    val m = heights.size
    val n = heights[0].size
    if (row !in 0 until m || col !in 0 until n) return
    if (visited[row][col]) return
    if (row == m - 1 && col == n - 1) {
        allEfforts.add(currentEffort)
        return 
    }

    visited[row][col] = true
    for (d in directions) {
        val newRow = row + d[0]
        val newCol = col + d[1]
        if (newRow !in 0 until m || newCol !in 0 until n) continue
        if (visited[newRow][newCol]) continue

        val newEffort = abs(heights[row][col] - heights[newRow][newCol])
        dfs(heights, newRow, newCol, visited, maxOf(currentEffort, newEffort), allEfforts)
    }
    // Backtrack
    visited[row][col] = false
}
```

- Time complexity: We are going to find all the possible paths so we need to backtrack at each position, and there are at most 3 adjacent nodes to visit next, the time complexity is `3^(m x n)`

   - `O(m x n)`, this is wrong as we are exploring the possible paths from a single node, the time complexity is `O(m x n)` for a single path, it's not the total complexity.

### Bottleneck

Suppose we have exact two paths A and B, path A has all minimum efforts, path B has all maximum efforts, then exploring path B is a waste.

```js
1a, 100
1b, 1c

1a -> 100 -> 1c: 99
1a -> 1b -> 1c: 0 (winner)
```

### Pattern Recognition

- What if we can always explore the minimum effort at each step, then see if we can reach the destination. If not, we explore the sub-optimal path after that.
- We prioritize to visit the path with minimum effort at each step.

→ Priority Queue + Dijkstra’s

## Dijkstra
Explore the path greedily, always choose the path with the minimum effort.

```kotlin
fun dijkstra1(heights: Array<IntArray>): Int {
    val m = heights.size
    val n = heights[0].size
    val efforts = Array(m) { IntArray(n) { Int.MAX_VALUE } }
    val minHeap = PriorityQueue(compareBy<EdgeState> { it.effort })
    minHeap.add(EdgeState(0, 0, 0))
    efforts[0][0] = 0

    while (minHeap.isNotEmpty()) {
        val (x, y, effort) = minHeap.poll()
        if (effort > efforts[x][y]) continue
        if (x == m - 1 && y == n - 1) return effort

        for (d in directions) {
            val newRow = x + d[0]
            val newCol = y + d[1]
            if (newRow !in 0 until m || newCol !in 0 until n) continue

            val nextEffort = abs(heights[newRow][newCol] - heights[x][y])
            // Update the effort to accumulate the adjacent cell.
            // We need to carry the accumulated path cost forward
            val newEffort = maxOf(effort, nextEffort)
            if (newEffort < efforts[newRow][newCol]) {
                minHeap.add(EdgeState(newRow, newCol, newEffort))
                efforts[newRow][newCol] = newEffort
            }
        }
    }
    return -1
}
```

- **Time Complexity:** `O(m * n * log (m * n))`.
    - Dijkstra: `O((V + E) * log V)` or `O(E * log V)`, `V = m * n`, `E = 4 * V` (4 directions)
- **Space Complexity:** `O(m * n)` for distances and priority queue.

## Binary Search
*Min-Max* 為何是二分？ 
- 裡面的 Max: 在 1631 題中，我們看的是「Maximum Effort（路徑上的最大高度差）」。在物理上，你可以把這個 Maximum 想像成你的「腿長限制」。如果你選定了一條路徑，這條路徑的 Maximum Effort 是 K，意思就是：「只要你的腿長有 K，你就能無懼路徑上的任何起伏，順利走到終點。」
- 外面的 Min:「為了順利走到終點，我的腿長『至少』要多長？」。我們就從 1, 2, 3, ... 開始往上找，看看這樣能不能走到終點？可以發現，答案呈現 `X, X, X, O, O, O` 的狀態，在超過某個數值之後就開始都可以通過 (單調性)，這就是一個典型的二分搜尋問題了。

> We use _effort_ to represent the _maximum absolute difference_ in heights between two consecutive cells of the route. (Aligned the problem description)

Let's take a look how do we apply binary search on answer in this problem:

1. Search range: Given a minimum and maximum in the grid, the possible maximum effort = `abs(max - min)`, the possible minimum effort is `0` (same height).
2. Monotonicity: If there exists a path which effort is `k`, then we can definitely find a path which effort is `k + 1` or larger `k`. (It's constraints)

We guess an effort `k` and check if there exists a path from source to destination that under that effort constraints. If we can reach the destination (via DFS or BFS), we try to find a smaller threshold. Otherwise, we try to find a larger threshold.

> 可以上下左右走，沒有無後效性，無法用動態規劃做。無腦搜索的話因為沒有什麼障礙或限制，效率非常差。可以二分猜答案;也可以貪心找 (Dijkstra's)，先找出所有的落差值，從最小的值開始串，看能不能串出從左上到右下的路徑。

```kotlin
fun minimumEffortPath(heights: Array<IntArray>): Int {
    val m = heights.size
    val n = heights[0].size
    var left = 0 // Minimum effort is 0, not 1, the height difference can be 0. (same height)
    var right = abs(heights.maxOf { it.max() } - heights.minOf { it.min() })
    while (left <= right) {
        val middle = left + (right - left) / 2
        val canReach = dfs(heights, 0, 0, Array(m) { BooleanArray(n) }, middle)
        if (canReach) {
            right = middle - 1
        } else {
            left = middle + 1
        }
    }
    return left
}

// We traverse the grid using DFS and check if we can reach the destination with the threshold.
private fun dfs(
    heights: Array<IntArray>,
    x: Int,
    y: Int,
    visited: Array<BooleanArray>,
    threshold: Int
): Boolean {
    val m = heights.size
    val n = heights[0].size
    if (x == m - 1 && y == n - 1) return true
    visited[x][y] = true

    var result = false
    for (d in directions) {
        val newX = x + d[0]
        val newY = y + d[1]
        if (newX !in 0 until m || newY !in 0 until n) continue
        if (visited[newX][newY] == true) continue
        val diff = abs(heights[x][y] - heights[newX][newY])
        if (diff <= threshold) {
            result = dfs(heights, newX, newY, visited, threshold) || result
        }
    }
    return result
}
```

- **Time Complexity:** `O(m * n * log(R))` where `R` is the maximum possible value range.
- **Space Complexity:** `O(m * n)`.

## Prim Variants
```kotlin
fun primVariants(heights: Array<IntArray>): Int {
    val m = heights.size
    val n = heights[0].size
    val minHeap = PriorityQueue(compareBy<EdgeState> { it.effort })
    val efforts = Array(m) { IntArray(n) { Int.MAX_VALUE } }
    minHeap.add(EdgeState(0, 0, 0))
    efforts[0][0] = 0
    var minEfforts = 0
    while (minHeap.isNotEmpty()) {
        val (x, y, effort) = minHeap.poll()
        if (efforts[x][y] < effort) continue

        // Keep a running high-water mark of the maximum effort along the path to reach (x, y)
        minEfforts = maxOf(minEfforts, effort)
        if (x == m - 1 && y == n - 1) break

        for (d in directions) {
            val newX = x + d[0]
            val newY = y + d[1]
            if (newX !in 0 until m || newY !in 0 until n) continue
            // We don't take the max of current effort and next effort.
            // This drops history and only evaluated the immediate edge.
            val nextEffort = abs(heights[newX][newY] - heights[x][y])
            if (efforts[newX][newY] > nextEffort) {
                efforts[newX][newY] = nextEffort
                minHeap.add(EdgeState(newX, newY, efforts[newX][newY]))
            }
        }
    }
    return minEfforts
}
```

### 關鍵總覽

**What（核心差異）**：
True Dijkstra 是「尋找路徑」，必須攜帶歷史狀態；你的變形版（本質為 Prim 演算法）是「擴張領地」，只看當下這一步的成本，丟棄了歷史。

**Why（為什麼變形版也能算對）**：
變形版每次都挑選全圖邊界上最小的「單一邊」來走，這其實是在無向圖中建構**最小生成樹 (MST)**。MST 的數學特性保證了：樹上任兩點的路徑，必定是「最大邊權最小 (Min-Max)」的最佳解。但因為它不攜帶路徑歷史，必須額外依賴一個全域變數 (`minEfforts`) 來幫忙記住整趟擴張過程中遇到的最大瓶頸。

## Key Overview

* **What:** The fundamental difference between True Dijkstra (Path-Finding) and your variant (Prim's Tree-Building) comes down to **Historical State Tracking**. Dijkstra carries the accumulated path cost forward, while the variant drops history and only evaluates the immediate edge.
* **Why:** True Dijkstra works because it strictly evaluates complete paths, guaranteeing the optimal route. Your variant works specifically for "Min-Max" (bottleneck) problems because expanding the cheapest local edge builds a Minimum Spanning Tree (MST). A mathematical property of MSTs is that the path between any two nodes inside it is inherently the minimax path.

---

### **1. True Dijkstra (Stateful Path-Finding)**

* **The Mechanism:** It constantly asks, *"What is the cost of the entire journey from the start to this node?"*
* **The Formula:** `newEffort = maxOf(accumulatedHistory, currentEdge)`. The state of the largest hurdle is physically attached to the node and passed forward.
* **Queue Behavior:** The Min-Heap sorts paths based on their true historical bottleneck.
* **First Principle:** Cost is monotonic. By always expanding the route with the smallest historical bottleneck, it is impossible to find a better route later. The first time the target pops, you have the answer.

### **2. The Prim's Variant (Stateless Tree-Building)**

* **The Mechanism:** It constantly asks, *"What is the absolute cheapest single step I can take to expand my explored territory?"*
* **The Formula:** `newEffort = currentEdge`. The history of how you reached the current node is intentionally forgotten.
* **Queue Behavior:** The Min-Heap sorts strictly by the smallest available local jump anywhere on the frontier.
* **First Principle:** By greedily absorbing the smallest connecting edges, you grow an MST. A global tracking variable (`minEfforts = maxOf(minEfforts, poppedEdge)`) acts as a high-water mark. When the target cell is finally absorbed into the territory, that high-water mark accurately reflects the largest bottleneck encountered.

### **Comparison Summary**

| Feature | True Dijkstra | Prim's Variant (Your `dijkstra2`) |
| --- | --- | --- |
| **Core Focus** | Complete Path Cost | Single Edge Cost |
| **State Passed Down?** | **Yes** (`maxOf(history, edge)`) | **No** (History dropped) |
| **Queue Sorts By** | Maximum bottleneck of the *route* | Smallest *jump* on the frontier |
| **Global Tracker** | Not needed | **Required** (`minEfforts`) |
| **When to use?** | Standard Shortest Path (Sum, Max) | Minimax / Spanning Tree problems |
| **Fatal Flaw** | None | Will fail instantly if the problem asks for the *sum* of edge weights |
