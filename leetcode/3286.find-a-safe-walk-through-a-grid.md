# [3286. Find a Safe Walk Through a Grid](https://leetcode.com/problems/find-a-safe-walk-through-a-grid/)

## Multi-State Traversal
We can arrival at the same cell `(x, y)` with different health values:
* Arrival at `(2, 3)` with health = `5`, it's more likely to succeed.
* Arrival at `(2, 3)` with health = `3`.

It's multi-state traversal and the reachability problem.

> It's intuitive but not optimal solution, it's vulnerable to an explosion of re-evaluations that might cause TLE.

```kotlin
data class State(
    val x: Int,
    val y: Int,
    val health: Int
)

fun findSafeWalk(grid: List<List<Int>>, health: Int): Boolean {
    return dfs(grid, 0, 0, health, HashSet<State>())
}

private fun dfs(grid: List<List<Int>>, x: Int, y: Int, health: Int, visited: HashSet<State>): Boolean {
    val m = grid.size
    val n = grid[0].size
    // Out of bound
    if (x !in 0 until m || y !in 0 until n) return false

    // Invalid
    val newHealth = health + (if (grid[x][y] == 1) -1 else 0)
    if (newHealth <= 0) return false

    // Visited
    val newState = State(x, y, newHealth)
    if (newState in visited) return false

    // Target
    if (x == m - 1 && y == n - 1) return newHealth > 0

    // Normal traversal
    visited.add(newState)
    for (d in directions) {
        val newX = x + d[0]
        val newY = y + d[1]
        if (dfs(grid, newX, newY, newHealth, visited)) return true
    }
    return false
}
```

- **Time Complexity**: O(m * n * h), where h is the initial health.
- **Space Complexity**: O(m * n * h), for the visited set.

## Dijkstra
The problem doesn't ask for the shortest path explicitly, it needs a simple mathematical pivot. Our goal is to reach the bottom-right corner with positive health, we can write the formula as:

```js
Initial Health - Total Damage > 0
```

Since our initial health value is fixed, the **only** way to maximize the change to survival is to make the total damage as small as possible. In graph theory, "shortest path" doesn't necessarily mean "the fewest steps", it means **"the lowest total cost"**:

- When stepping into `0`, the cost is `0`.
- When stepping into `1`, the cost is `1`. 

The problem translates from "Find a path that keeps my health > 0" to "Find a path that has the **minimum total cost**". This is exactly what Dijkstra's algorithm is designed for.

In multi-state traversal, we have to explore the path which arrives at the same cell with different health. But in Dijkstra's algorithm, if we found a path arriving at `(2, 3)` has the minimum `1` damage, then all the paths to `(2, 3)` with health > `1` are useless. Based on the greedy property in Dijkstra's algorithm, when the first time we pop the node with the highest remaining health, it's mathematiically impossible for any future path to reach that cell with higher health.

> - BFS/DFS: Process by steps/depth. They find bad paths first, forcing them to re-add cells to the queue constantly when safer, longer paths are discovered later.
> 
> - Dijkstra / 0-1 BFS: Process by health. The first time a cell is popped, it is permanently locked in as the safest path. No re-evaluations needed. Time complexity stays strictly bound.

這題有一個重點要特別注意，當我們到一個節點 `(x, y)` 時，我們會帶一個健康值進入，在我們一些操作上要注意這個健康值是否已經更新過了。例如，我們剛進入 `(2, 3)` 的時候 `health = 5`，而該節點是 `1` 我們理當扣除，問題是在 Dijkstra's 的過程中何時要更新？以及我們狀態存的是更新前還是更新後的值？

```js
5 -> (x, y) health = 4
```

Always record the updated health: 
- State matrix
- Heap

There are 3 timing to calculate the health:
1. Enqueue the source: Check if cell is 1 and enqueue the updated health.
2. Pop from PQ: No update, the value has already been updated when enqueuing.
3. Check neighbors: Execute only popped health > 0, update the neighbor’s health and then relax.

```kotlin
data class State(
    val x: Int,
    val y: Int,
    val health: Int
)

fun findSafeWalk(grid: List<List<Int>>, health: Int): Boolean {
    val m = grid.size
    val n = grid[0].size
    // Record the exiting health value for each cell
    val healthGrid = Array(m) { IntArray(n) }
    // Greedy on larger health
    val heap = PriorityQueue(compareByDescending<State> { it.health })

    // Remember to enqueue the "updated" health
    val startHealth = health + (if (grid[0][0] == 1) -1 else 0)
    if (startHealth <= 0) return false
    heap.add(State(0, 0, startHealth))
    healthGrid[0][0] = startHealth
    while (heap.isNotEmpty()) {
        // The health has been updated when enqueuing, don't update here!!
        val (x, y, currentHealth) = heap.poll()

        // Stale
        if (healthGrid[x][y] > currentHealth) continue

        // Target 
        if (x == m - 1 && y == n - 1) return currentHealth > 0

        // We don't check neighbors when health drops to 0
        if (currentHealth == 0) continue
        
        // Relaxation
        for (d in directions) {
            val newX = x + d[0]
            val newY = y + d[1]
            if (newX !in 0 until m || newY !in 0 until n) continue

            // Remember to update the health when enqueuing and set the state
            val newHealth = currentHealth + (if (grid[newX][newY] == 1) -1 else 0)
            if (healthGrid[newX][newY] < newHealth) {
                healthGrid[newX][newY] = newHealth
                heap.add(State(newX, newY, newHealth))
            }
        }
    }
    return false
}
```

- **Time Complexity**: `O(m * n * log(m * n))`.
- **Space Complexity**: `O(m * n)`, for the health grid and the heap.
