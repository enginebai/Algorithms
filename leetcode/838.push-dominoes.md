# [838. Push Dominoes](https://leetcode.com/problems/push-dominoes/)

## Derivation
- Abstraction: We evaluate the final state of each domino by calculating the fastest arrived force to that from left or right. Because dominoes fall at a constant speed of 1 unit per second, the force that travels the shorter distance will hit first and determine its final direction.

   - If there are two forces, take the shorter one (faster arrival). If two forces arrive at the same time, they cancel out and the domino remains standing.
   - If only one force, take that directly.
   - Otherwise, stay unchanged.

- Brute force: 
    - Approach 1: For each position, we go left and right to search the first opposite force.
    - Approach 2: Simulate the time elapsing second by second, move the force by updating their adjacent `.` neighbors and resolve the collisions until no more changes occur.

- Bottleneck: 
    - Approach 1: For the same force and two different positions, we recalculate the same distance from the beginning.
    ```js
    _, _, _, R, _, x, y, ...
             |----->
             |-------->
    ```
    - Approach 2: A simulation takes `O(N^2)` time in the worst case (e.g., an input like `"R........."`, where a single push takes `N` steps to reach the end). We are redundantly looping over the exact same empty spaces just to simulate the passage of time.

- Pattern recognition: This is a classic *Two-Pass Traversal* (Prefix & Suffix Arrays) problem. We can precalculate the arrival times using two independent sweeps across the array.

```js
Dominoes:   .  L  .  R  .  .  .  L

distR:      ∞  ∞  ∞  0  1  2  3  ∞   (Distance from nearest 'R' to the left)
distL:      1  0  ∞  ∞  3  2  1  0   (Distance from nearest 'L' to the right)

Compare:    L  L  .  R  R  .  L  L   (Smaller distance wins; equal is '.')
```

- **Edge Cases & Potential Pitfalls**

    - **Isolated standing dominoes:**`"."` strings with no forces at all. Initializing unreachable states to `Int.MAX_VALUE` elegantly solves this, as both `distR` and `distL` will equal `Int.MAX_VALUE`, defaulting to `.` correctly.
    - **Shadowing forces:** When an `L` is to the right of an `R` (e.g., `R...L`), the forces collide. However, when an `R` is to the right of an `L` (e.g., `L...R`), they fall away from each other and exert no force on the middle spaces. Setting `distance = -1` when hitting an opposing domino perfectly models this blocked force behavior.


```kotlin
fun pushDominoes(dominoes: String): String {
    val n = dominoes.length
    val leftForces = IntArray(n) { Int.MAX_VALUE }
    val rightForces = IntArray(n) { Int.MAX_VALUE }

    var right: Int? = null
    // Find the closest R force on left
    for (i in dominoes.indices) {
        if (dominoes[i] == 'R') {
            right = i
        } else if (dominoes[i] == 'L') { // The rightward force is blocked by 'L'
            right = null
        }
        if (right != null) {
            rightForces[i] = i - right
        }
    }
    var left: Int? = null
    for (i in n - 1 downTo 0) {
        if (dominoes[i] == 'L') {
            left = i
        } else if (dominoes[i] == 'R') { // The leftward force is blocked by 'R'
            left = null
        }
        if (left != null) {
            leftForces[i] = left - i
        }
    }
    var answer = StringBuilder()
    for (i in dominoes.indices) {
        val finalState = if (leftForces[i] < rightForces[i]) 'L'
            else if (leftForces[i] > rightForces[i]) 'R'
            else '.'
        answer.append(finalState)
    }
    return answer.toString()
}
```
